# Sieve Scope Engine Specification v1.3

- **Version**: 1.3 (Production Ready)
- **Status**: Final Specification
- **Compatibility**: v0_mask compatible with v0 & v1.2

---

## 1. Core Architecture & Pipeline

Sieve Scope v1.3 evaluates pairs of Python code (`code1`, `code2`) through a
pipeline of hypotheses ($H_1 \sim H_7$) and guarantees deterministic results.

[Code Pair] ──> H1 (Parse) ──> H2 (Skeleton) ──> H3 (Identifiers) ──> [Short-Circuit Check]
│ (H2=0 and H3=0)
├──> YES: Return "1000-000"
└──> NO : Continue to H5, H6, H7



---

## 2. Hypothesis Definitions and Implementation Rules

### H1: Parseability

- **Definition**: Both inputs can be parsed by `ast.parse()` without a `SyntaxError`.
- **Rule**: If either input raises a syntax error, return the mask `0000-000` immediately with `short_circuited=True`.

### H2: AST Skeleton Matching

- **Definition**: Depth-first AST node-type sequence produced by `ASTSkeletonVisitor.generic_visit()`.
- **Implementation note**: The current implementation includes node types such as `Load`, `Store`, `Del`, and operator nodes such as `Add`, `Sub`, `Mult`, etc. It is not a pruned semantic skeleton.

### H3: Pure Identifier Similarity

- **Definition**: Extract non-keyword `NAME` tokens in order using `tokenize`, then compute:
score = 0.6 * Multiset Jaccard + 0.4 * SequenceMatcher ratio

- **Threshold**: H3 = 1 when `score > 0.50` (strict greater-than, preserving v0 behavior).
- **v0-compatible ignored words (`IGNORED_WORDS_V0`)**:

```python
{'print', 'len', 'range', 'sum', 'int', 'str', 'self', '__init__'}

H4: Cluster Safety Invariant
Definition: H4 = 1 only when all of the following are true:

both items belong to the same valid cluster,

the cluster size is at least min_cluster_size (default 3),

the pair itself has direct H2 or H3 evidence.

Pair evaluation rule: evaluate_pair() always returns H4=0 because no cluster context is available.

Corpus evaluation rule: SieveClusterAnalyzerV1_3 promotes H4 only after cluster validation.

Indirect paths must never manufacture direct H4 evidence.

H5: Positional AST Structure (g_POS)
Definition: SHA-256 hash of the recursive AST field representation generated by build_pos_tuple().

Implementation note: build_pos_tuple() excludes fields named value, id, and attr when the field value is not an AST node. Other scalar fields, including arg.arg, are retained. Therefore H5 is not a completely identifier-erased representation.

H6: Constant Signature (g_CONST)
Definition: Collect all ast.Constant values, convert each to its string form, sort the resulting list, and compare for exact equality.

H7: Weighted Bi-gram Dice Coefficient (g_FREQ)
Definition: Extract identifier sequence, generate bi-grams, and compute:

Dice = (2 * sum(min(count1(bg), count2(bg)))) / (total_bigrams1 + total_bigrams2)

Threshold: H7 = 1 when Dice >= 0.60.

Implementation note: Each bi-gram occurrence is accumulated with weight 1.0 using defaultdict(float). The weighted intersection is computed as the sum of the minimum counts for common bi-grams.

3. Short-Circuit Rules and Mask Outputs
Parse Error: H1=0 -> v0_mask="0000", mask="0000-000", short_circuited=True

No Direct Similarity: H2=0 and H3=0 -> v0_mask="1000", mask="1000-000", short_circuited=True; H5, H6, and H7 are skipped.

H2=0 and H3=1 is a similarity case and must not be treated as a short-circuit case.

4. Default Parameters
Parameter	Value	Rationale
jaccard_threshold	0.50	v0_mask compatibility and optimal F1 on the synthetic validation set
freq_dice_threshold	0.60	Noise reduction for weighted token continuity
IGNORED_WORDS_V0	8 words	v0 regression compatibility
min_cluster_size	3	Safety invariant requirement

5. Observation Space and Equivalence
Sieve Scope v1.3 projects a code pair into a 7-bit binary observation:

text
f_v1.3(code1, code2) = (H1, H2, H3, H4, H5, H6, H7)
A mask of 1110-111 means that the two codes are identical in the current observation space. It does not guarantee semantic equivalence.

6. Validation Scope
The default thresholds were calibrated on a small synthetic dataset containing 6 positive pairs and 3 negative pairs. The reported F1 score of 1.0 applies only to that synthetic validation set and is not a production accuracy guarantee.

Cross-Python validation was performed on Python 3.9, 3.10, 3.11, and 3.12.
